## Things the auditor missed (or under-weighted)

1. **BANKED Shield payload bug is confirmable from code, not an open question.** `SoloBattle.cs:1677` emits `new BattleEvent(BattleEventKind.Shield, 0, (int)MathF.Round(bankedShield), ms)` — a magnitude — while `SoloBattle.cs:1962` emits `UndyingShieldMs` — a duration — and `WaveReplay.cs:371` reads every Shield as `_shieldUntil[e.Slot] = e.AtMs + e.Amount` (ms). `IsShielded` (`:134-135`) therefore shows SNARE's banked shield for "bankedShield" milliseconds. The remark at `:1958-1961` shows the same unit bug was already fixed once for UNDYING. This is the house species (dormant feature, green tests) and should be a finding with a failing test, not §11 Q5.
2. **`Game1.cs:735` is a crash path on region rename** (see #33). The report's migration advice (alias table in `SaveSystem` load) is right but the report describes the current behaviour as silent loss; it is a `KeyNotFoundException` before any farm is restored.
3. **`SoloExpeditionScreen.EnemySource` is live** (see #5). The report's §1.3 row would have deleted the property that selects enemy art (`EnemyForSource` at `:1723,1839,1849`), the enemy name (`:1880`) and the Source glyph (`:2426`).
4. **Grep scope was inconsistent with the stated method.** §0 says every dead claim is backed by a grep over `src` *and* `tests`, but #10, #11, #17, #18 were grepped over `src` (or `Game`) only. Test readers exist for all four: `SkillShapeBattleTests.cs` (WaveMetrics), `SoloExpeditionTests.cs` + `live_build_test.cs` (Carried), `MemoryDustTests.cs:238` (OptimizedTeam). None block deletion, but each deletion is a test rewrite too.
5. **Line numbers for five Core files do not match the working tree**: `BandCycles.cs` (151 lines; report cites 225–331), `RegionModifiers.cs` (35; cites 229–239), `RegionLadder.cs` (73; cites 181–197), `RunLog.cs` (136; cites 302–346), `ExpeditionLoot.cs` (119; cites 216–219). The symbols and behaviour are as described, so this is not a substance error, but anyone applying the report must locate by symbol. The other files (`SoloExpedition.cs`, `SoloBattle.cs`, `WaveReplay.cs`, `RunReport.cs`, `Game1.cs`, `SoloExpeditionScreen.cs`, `SaveGame.cs`, `Regions.cs`, `Bands.cs`) check out line-for-line.
6. **`SkillDef.ClipKey` exists but the screen derives the champion clip from the Form enum name.** `SkillCatalogue.cs:166` declares `string ClipKey` on `SkillDef`; `SoloExpeditionScreen.cs:3280` does `clip = ((Form)nextSkill.Amount).ToString().ToLowerInvariant()`. The event re-key (§2.3) has a ready-made target for this branch that the report does not name.
7. **The Form-keyed Core surface is four methods, not two overload pairs.** `WaveReplay.NextSkillEventAfter` (`:167-174`) and `LastTrapBefore` (`:298-308`) are consumed by the screen at `:3277` and `:3297` and branch on `Form.Trap` inside Core; they need the same slot/flag treatment as `NextSkillAfter/LastSkillBefore`.
8. **`Region(id, parClearTimeSeconds)` ctor footprint** — `SaveSystemTests.cs:23,470` and `TraitNamesTests.cs:233-234` construct `Region` with the par argument. The report lists only `FullLoopTests.cs:36`.
9. **`WorldTests.cs:15`** (`Assert.All(Regions.All, r => Assert.Contains(r.Templates, t => t.IsBoss))`) pins `RegionDefinition.Templates` and is not in the report's deletion list.
10. **`Game1.cs:1843`** (dev `bossdebug` path) sets `_expedition.EnemySource = Source.Mind` — a second writer of the screen property, relevant if the property is ever narrowed.
11. Minor stale doc: `RegionDrops.cs:33` claims "the MAP … lists `FavouredNames` one per line"; the map calls `PlainName` directly (`MapScreen.cs:569`).
