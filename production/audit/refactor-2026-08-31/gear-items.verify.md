## Headline corrections (read these before any destructive edit)

1. **The six combo-trigger battle branches are NOT enchant-specific.** `MasteryCatalog.cs:433-448` (`Specialisations`) grants `BuildTrigger.Execute / Coiled / Overdraw / Radiance / Linger / Siphon` from six skill-tree notables; they reach the fight through `BuildComposer.cs:129` → `Build.ExtraTriggers` → `Build.Triggers` (`Build.cs:588`), the same set the enchants feed (`Build.cs:589-590`). Collapsing the enchants into `Func<SkillDef,SkillDef>` deltas and deleting the `triggers.Contains(...)` branches (claims 1, 3, 28-30) would silently orphan those six mastery nodes — the exact "node that does nothing" failure `SoloBattle.cs:443-445` warns about.
2. **`EquippedToCreatureId` is NOT always null in real saves.** The legacy-save fixture `SaveSystemTests.cs:115-124` (a pre-2026-08-24 save) carries `"EquippedToCreatureId": "start_atk"`, and `FromSavedItem` round-trips it (`SaveGame.cs:587`). Such an item today fails `Forge.CheckEligible` (`Forge.cs:101`) with "EQUIPPED TO A CREATURE. UNEQUIP IT FIRST." at `ForgeScreen.cs:876/904/2789` and inside `Forge.Merge` (`:156`) — and nothing can clear it, because no assignment site exists. Deleting the field/gate is still right (it fixes this), but the premise "the gate can only return Eligible" is false for legacy saves.
3. **Deleting `ItemBaseType.CreatureCore` / `Material` would crash legacy loads.** `SaveGame.cs:583` and `:589` use strict `Enum.Parse<ItemBaseType>(s.BaseType)`; pre-pivot saves held Material items and cores (the fixture's `UnhatchedCores`, retired 2026-08-24). Claim 9's "consider deleting" sub-recommendation needs a lenient parse or a migration first.
4. **Line numbers drift.** `MergeRecipe.cs` is 143 lines; every cite of it (`:241-253, :265-270, :273-277, :310-314`) is wrong — real lines are `:69-81` (HybridTable), `:93-98` (HybridPriority), `:101-105` (HasRecipe), `:138-142` (Key). `HunterProgression.cs` cites run ~38 lines early in places (`Sell` is `:527-536` not `:489-499`; the `EquippedToCreatureId` filter is `:531` not `:494`; `MaxHealth` is `:236` not `:225`; `CharmToughness` is `:420-421` not `:415-416`). `PlayerLoadout.cs` is in `src/ResonanceHunter.Game/`, not Core.
5. **`BonusRollAttempts` is live**, not a dead knob — read at `LootSystem.cs:328` inside `DropCount`, which `RollBoss` → `Roll` → `DropCount` calls on every chest open. §8 of the report lists it among "never set by a live caller"; the CLAIMS list correctly omits it.

## Things the auditor missed

- **Mastery Specialisations grant all six combo triggers** (`MasteryCatalog.cs:433-448`), so the battle's `triggers.Contains(BuildTrigger.X)` branches have two content authors; any refactor of the enchants must carry the six skill-tree nodes (and `character?.Grants`, `BuildComposer.cs:130`). Not mentioned anywhere in the report.
- **Legacy saves can hold a non-null `EquippedToCreatureId`** (`SaveSystemTests.cs:122`), which today permanently blocks sell/salvage/merge on that item with a message about a creature that no longer exists (`Forge.cs:101,109`, `ForgeScreen.cs:876,904,2789`). A live legacy bug the deletion happens to fix.
- **Strict `Enum.Parse<ItemBaseType>` at `SaveGame.cs:583,589`** means deleting `CreatureCore`/`Material` from the enum crashes any legacy load still holding one — the report's §9.5 table omits `BaseType`.
- **`RollBoss.Take(count)` before the Material filter** (`ExpeditionLoot.cs:116` → `Chest.cs:344`) under-delivers the chest's promised item count roughly 45% of the time; the report notes the back-fill but not the lost second item.
- **RNG draw-order coupling**: removing the core mint and Material branch shifts every subsequent `rng.Next` — 36 seeded-`Random` tests in Loot/Expeditions/integration and the fixture-pinning note at `LootSystem.cs:294-295` will need re-pinning.
- **`BonusRollAttempts` is live** (`LootSystem.cs:328`), contradicting report §8's "never set by a live caller" list.
- **`MergeRecipe.HasRecipe` has zero callers anywhere** (src or tests) — report says "tests only".
- **Splinter's Blurb never prints the magnitude** (`Enchantments.cs:147`), so report Q7's "the blurb cannot lie" concern is moot.
- **Three `Forge.CheckEligible` callers in `ForgeScreen.cs` (`:876, 904, 2789`)** are not listed among the gate's consumers.
- **Test files that reference deletion candidates** (must be edited alongside): `ForgeTests`, `SalvageTests`, `MergeRecipeTests`, `charters_test`, `LootSystemTests`, `FullLoopTests` (integration), `attrition_test`, `progression_curve_test`, `SaveSystemTests` (legacy fixture with `EquippedToCreatureId` and `AutomationStage`), `LootElementTests`, `region_drops_test`, `item_classes_test`.
- **`PlayerLoadout` lives in the Game project**, so the Form→Style bridge the migration depends on is presentation code, not Core; a Core-side loader bridge must be written new.
- **Wholesale line-number errors in `MergeRecipe.cs` cites** (file is 143 lines; report cites `:241-314`) and ~38-line drift in `HunterProgression.cs` — anyone editing by line number from the report will hit the wrong code.
