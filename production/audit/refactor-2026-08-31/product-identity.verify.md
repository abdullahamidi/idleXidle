## What the audit missed

1. **Save enums are name-bound, not ordinal-bound** (detail in #19). The audit's hand-off to the legacy-Form area ("enum ORDINALS must not be reordered") would let a member *rename* through and block a harmless reorder. Concretely: `Automation.Source` values are persisted as the item `Element` string (`SaveGame.cs:572/:590`), `SavedSkill.Source`/`Form` are strings (`:296-297`), `ItemBaseType`/`GearTrait`/`EnchantKind`/`ItemClass`/`HunterStat`/facility and charter enums are all written with `.ToString()`. Renaming or deleting any of those members is the save risk; `Rarity` (`:563`) is the only ordinal.
2. **The whole MGCB wiring is dead, not just the empty `Content.mgcb`**: `MonoGame.Content.Builder.Task` `PackageReference` (`Game.csproj:33`), the `RestoreDotnetTools` target that shells `dotnet tool restore` on every build (`Game.csproj:74-77`), and `.config/dotnet-tools.json` (five `dotnet-mgcb*` tools, 3.8.4). Zero `Content.Load` calls in src; only `Content.RootDirectory = "Content"` boilerplate at `Game1.cs:433`. CI log 33390896201 shows "Restoring dotnet tools…" running twice per run. Removing the three together is the real win; verify with `dotnet build` afterwards.
3. **The shipped install folder still shows the old name to players**: `build/release/IDLExIDLE-win64/ResonanceHunter.Core.dll` + `ResonanceHunter.Core.pdb` (and `IDLExIDLE.deps.json` names that assembly). §1/§3.7's "zero player-visible old-name strings" only considered UI text; Explorer shows this next to `IDLExIDLE.exe`, same class of exposure as the save folder. The Core project rename fixes it; it should be listed as a player-visible motivation, not only a tidy-up. (Also: `.pdb` files ship in the release — unrelated to identity but visible in the same listing.)
4. **`Enum.Parse<ItemBaseType>` is strict** (`SaveGame.cs:582`, `:586`): an unknown `BaseType` name throws `ArgumentException`, which `SaveSystem.Deserialize` (catches `JsonException` only, `:466-470`) does not see; `RestoreInventory` is called unguarded from `Game1.cs:700`. Any identity or legacy rename touching `ItemBaseType` member names bricks the load instead of quarantining it. Adjacent to this area's save-risk section; belongs in the legacy-Form hand-off.
5. **`ci.yml:16-19` says `Set up .NET 8` / `dotnet-version: '8.0.x'` while the job actually builds with a newer image SDK** — the audit noted "no `global.json`" but not that the workflow's own declared toolchain is false. Whichever fix is chosen (`.sln` or `global.json`), make `ci.yml:19` state the SDK that really runs; a `global.json` pinned to `9.0.200` with `setup-dotnet` still installing only 8.0.x depends on the runner image happening to ship a 9.0.x SDK.
6. Minor count corrections for the plan's definition-of-done: 9 agent-memory files (not 10); 19 design title lines (not 25); Game1.cs has 34 raw `RH_` reads (not ~40) — 43 total. None changes a decision.
