## 2. What the auditor missed

1. **`ItemClassDef.ChampionIds` is the dead half of duplicate #34.** `grep ChampionIds src` → `ItemClasses.cs` only; readers are `item_classes_test.cs` ×3 and `champion_tiers_test.cs:139-140`. `Character.Class` is read by `CanWear`, drops, trader, `UiKit.ClassColor`, every screen. The report's "one could be derived from the other" is undirected — the derivable one is already unread.
2. **`CharacterRoster.ByClass` has zero consumers** (src or tests) — the helper the report recommends deriving the grid from is itself dead code today.
3. **Half the bow's weapon affinity is as dead as oathbound's aptitude.** `ItemFamilies.FavouredForms` bow → `{Projectile, Mark}` at ×1.25 (`ItemFamilies.cs:51,58`) writes `FormPower[Mark]` through `GearShape.Of` (`GearShape.cs:22-29`) — the same channel #13 proves Mark never reads. The report lists bow→Projectile/Mark in §7 without flagging it.
4. **`QuestProgress` is a positional record struct** (`Quests.cs:91-95`); deleting `RegionsConquered` changes arity at 7 constructions (`Quests.cs:97`, `champion_tiers_test.cs:178-181` ×4, `quests_test.cs` ×2), not the two sites cited. Three unrelated live fields share the name (`UnlockFacts`, `TutorialFacts`, `SharedFeedback`).
5. **`CharacterUnlock.Quest(id, text)` is called from the frozen `LegacyUnlocks.cs:47,49`.** Deleting `QuestText` either edits the migration table or leaves a vestigial parameter — the report lists neither.
6. **`BattleEvent` carries no skill identity** (`WaveModel.cs:306`: `Slot` = `(int)Source`, `Amount` = `(int)Form` on Skill events, `SoloBattle.cs:1546,1717`). "View resolves clip from `Def.ClipKey`" needs a `BattleEvent` change or `SkillCatalogue.Resolve(form, passive)` (the `FxKey` path at `SoloExpeditionScreen.cs:3356` already does this). All 12 `ClipKey` values equal the lowercased Form name, so the swap is a no-op until the catalogue diverges.
7. **Every `LegacyUnlocks.cs` line citation in the report is wrong** (`:169-182`, `:203-209`, `:211-220`); the file is 91 lines. `Before` `:38-50`, `Seed` `:60-89`.
8. **`SavedSkill.Form` is a string, not an int** (`SaveGame.cs:297`) — Form is serialised by name; the skill area's Form deletion is a rename-safe/enum-drop-unsafe migration, not an ordinal one.
9. **STATS is a third consumer of `ChestsOpened`** (`StatsScreen.cs:68,536` via `Game1.cs:2730`). A Core career ledger must feed it too, not only the quest snapshot.
10. **The champion-id alias map (#29) has three more keyed tables**: `LegacyUnlocks.Before` (`LegacyUnlocks.cs:41-50`), `ItemClassDef.ChampionIds`, and the `roster_parity_test.ClaimedAxis` switch — a rename without touching those still breaks the legacy seed and the class catalogue.
11. **Branch→colour exists three ways**, not two: `RosterScreen.cs:97-103`, `BuildScreen.cs:1586-1592` (identical switch), and `UiKit.ClassColor` (`UiKit.cs:98-99`) mapping `ItemClass` to the same four hexes — so the class colour and the road colour agree only by copy.
