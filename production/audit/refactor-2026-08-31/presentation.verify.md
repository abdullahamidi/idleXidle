## What the auditor missed

1. **`SkillId` never reaches the composer from the Game.** `PlayerLoadout.ToBuild` (`PlayerLoadout.cs:270`) and both screen `SlotKinds` calls (`SoloExpeditionScreen.cs:861-863, :2861-2863`) construct `BuildComposer.SkillPick` without the sixth `SkillId` argument (`BuildComposer.cs:35-36`); `Restore` (`PlayerLoadout.cs:292`) drops it on load. `SkillChoice.SkillId` is read only by `Signature` (`:65`) and `WeaveScreen.cs:840, :1485`. `BuildComposer.cs:87` and `:171` ("THE ID WINS when there is one") are therefore unreachable in the running game — the Form+Passive bridge is the only skill identity the fight ever sees. This is the root under claim 38 and belongs in its migration step (carry `SkillId` on the pick and the save in the same commit).
2. **The sim still reads the Form cooldown table.** `BuildComposer.cs:179-180` seeds `EquippedSkill.CooldownMs` from `FormBehaviour.BaseCooldownMs(s.Form)` for every non-beat skill; `SoloBattle.cs:528` forks the opening pause on `FormBehaviour.CooldownBeats(f0)`; `:1412` reads `BaseCooldownMs(form)` for a spilled active. `CooldownMultiplier` is read only at `SoloBattle.cs:1908` (trap re-arm). The report's rail fix must not use `railDef.IntervalMs` (0 for all six Actives — `SkillCatalogue.cs:266, 323, 378, 433, 488, 543`); the skill-true ms source is the composed `EquippedSkill.CooldownMs`, which the screen does not hold (it draws `Loadout.Skills`, not `Build.Skills` — `:2855`).
3. **`FormHexDiagram` reads a live sim rule.** `FormBehaviour.AffinityFactor` is applied at `SoloBattle.cs:711, :788, :1585-1586, :1712-1713`; `BuildComposer.cs:128` sets `Affinity = mastery.Affinity()`; `WeaveScreen.cs:1108-1109` prints it. The proposed Style-ring replacement `SkillCatalogue.RingDistance` (`:661`) has zero non-test callers. "X ADEPT" Form copy also appears at `CharacterScreen.cs:553`, `StatsScreen.cs:226`, `BuildScreen.cs:715, :803` — the report lists only `SoloExpeditionScreen.cs:2340`.
4. **`BuildGlossary.FormRule` repeats the AuraTickMs mismatch on the weave screen.** `BuildGlossary.cs:49, :54` build user-facing text from `BaseCooldownMs(form)` and `AuraTickMs` ("Ticks every 1.0s") for every Field; consumed at `WeaveScreen.cs:1750, :1774`. PRESS/BRAND tick at 2000 ms (`SkillCatalogue.cs:293, :405`). Same root as claim 37; different screen; Core-owned copy (relevant to open question 7).
5. **`DrawBattleControls` is the rail's panel, not a tombstone.** Called at `:1471`; its one statement `:3122` `_ui.PanelQuiet(b, SkillRailMetrics().Rail)` frames the skill dock. The A-delete row in §9.2 would remove the frame.
6. **`SoloExpedition.ReplaceBuild` cannot see an active↔passive swap.** `SoloExpedition.cs:209-217` clears `ReadyAt/ReadyAtBeat` only when `Ability.Form` or `Ability.Source` changed — a BLOW→PRESS swap in one slot (same Form.Strike, same Source, `Passive` flipped) inherits the old cooldown entry. Presentation-triggered (the screen's stamp fires it, `:847-848`), and the report describes this method in §6.1 without noting the gap.
7. **Stale docs at the deletion sites.** `CanvasFit.cs:15-21` remark: "Integer scale only, always" (contradicted by `PresentFit`'s remark `:62-67`); `Clip.cs:31` broken `<see cref="Combat.Telegraph.WindupFloorMs"/>`; `AssetLibrary.cs:174-176` "one white strip per FORM"; `SoloExpeditionScreen.cs:3111-3112` summary still describes x1/x2/x4/x8 buttons.
8. **The aura total flushes on the fallback tick too.** `:1149` `_playheadMs > _auraTotalMs + FormBehaviour.AuraTickMs * 0.5f` — for a 2000 ms Field the aggregated number prints 500 ms after each tick; harmless, same root as 37, should move with it.
