## What the audit missed

1. **`Resolve(Form, passive)` is the live path, not a bridge** (claim 37). No `SkillPick` in `src/` carries a `SkillId`; `SavedSkill` has none; `EquippedSkill.Def` is `(Form, PassiveSlot)` at every fight read (`Build.cs:256`). The `SkillId` branch in `BuildComposer.cs:87-92, 171-172` is exercised only by tests — the very "built-tested-green, never runs" species the project watches for. Any Form retirement must start by threading `SkillId` through `SavedSkill` → `PlayerLoadout.SaveSkills/Restore/ToBuild` → `SkillPick` → `EquippedSkill`.
2. **The six Form-combo triggers are item enchantments too** (`Build.cs:602-607`, `Enchantments.cs:151-160, 175-180, 237`). Moving them "to SkillDef dials" leaves six item affixes with Form-keyed `EnchantNeed`s and no reader — or deletes them. The audit's replacement column never mentions items.
3. **Three live fields sit inside the cited delete ranges**: `ArmourPenetration` (`SkillShape.cs:123`), `OverkillCarry` (`:155`), `CooldownRefundOnKillMs` (`:230`) and their Combine lines `:496, :502, :516`.
4. **`AffinityFactor` / `Affinity()` have UI consumers outside SoloBattle**: `FormHexDiagram.cs:156, 172`, `WeaveScreen.cs:1108-1109`, `Game1.cs:2769`, `ChestScreen.cs:731-737`, plus the four `ADEPT` titles.
5. **Share codes drop `Passive`**: `WeaveScreen.cs:750-752` builds `SavedSkill { Source, Form, VowId }` without `Passive`, so which of a style's two skills was woven is not in the code (`ShareCodes.cs:222-229` does not validate it either). Display-only today (ChestScreen), so low stakes — but it is the same missing-`SkillId` problem as item 1.
6. **`RegionMasteryPoints` is live** (write `SaveGame.cs:552`, fallback read `Game1.cs:743`, six test pins) — the "delete after one version" needs those removed with it.
7. **`WarrenResource` is not persisted**; the JSON-name warning in claim 36 does not apply to the enum.
8. **`_deepestEver` does not drive mastery points** (`Game1.cs:252` comment and `:641` "Earned re-derives from it" are stale — `SkillPointsEarned` uses per-region `BestDepth`); it drives trader level, stats and the tree's unlock gate, which is why `MasteryEarned` must keep round-tripping.
9. **`MasteryPoints.cs:27-30` own remarks are stale** (256-point tree, "66 of 256") — the file the audit names as authoritative for the point rule.
10. **`MasteryCatalog.cs:450-457` is half-updated**: it says "Six nodes, six skills… 11 points" and, four lines later, "Twelve skills, twelve nodes" — both in one comment block.
